# KMedia Domain and Business Rules

This document defines the behavioral contracts and architectural invariants that apply across all modules in **KMedia**. Every C++ core service, media pipeline, and QML screen must respect these rules.

## 1. Congregation Profile Isolation and Switching

- Each congregation or language group profile owns an isolated SQLite3 database (`profile.db`), a dedicated media directory (`storagePath`), independent meeting schedules, and independent OBS/Zoom configuration.
- Registry metadata (`profiles.json`) must always be written atomically using `QSaveFile`.
- Deleting the last remaining congregation profile is rejected so the workspace always retains a valid active profile.
- Switching between profiles closes the active database cleanly, binds the target database and `SettingsStore`, and emits workspace reload signals in under `100 ms`.

## 2. Database and Disk Persistence Invariants

- SQLite3 opens in `WAL` mode (`synchronous = NORMAL`, `foreign_keys = ON`, `busy_timeout = 5000`, `mmap_size = 64 MB`) with versioned migrations tracked in `schema_migrations`.
- Multi-step playlist or catalog updates must execute inside explicit transactions with automatic rollback on failure.
- Empty optional text fields bind as empty strings rather than SQL `NULL` when stored in `TEXT NOT NULL` columns.
- Thumbnails are downscaled asynchronously to a bounded width (default `320 px`) on a capped worker pool (`<= 2` threads) and evicted strictly by LRU byte budget. Media rows show these cached thumbnails, never the full-size file: pictures and PDF pages come from the file itself, synced media from the preview picture JW.org publishes for it (`trackImage` in GETPUBMEDIALINKS, `images` in the Mediator, wide first and from the `sm` size up, downloaded next to the media before the media itself), and other videos and audio covers from a frame five seconds in (the first frame for shorter files) read by a headless mpv instance (`VideoFrameExtractor`). A file that cannot be decoded is not tried again until it changes.
- Opening a day reads its items and their media metadata in one joined query (`listPlaylistItemRows`), and image dimensions are captured once at import (`media_items.width`, `media_items.height`) instead of re-reading files on every load.

## 3. Dual-Monitor Presentation and Standby Rules

- Display monitoring reacts exclusively to `QGuiApplication::screens()` events (`screenAdded` / `screenRemoved`), with zero timer polling.
- When a secondary monitor is detected, the presentation output targets that display in borderless fullscreen unless a manual screen override is active.
- The external output window carries a consistent title (`"KMedia - Presentation"`) and composited backing so OBS Window Capture and Zoom Window Share capture cleanly without black frames.
- **Standby / Blackout Priority:** Activating Standby or Blackout takes immediate visual precedence over video, audio artwork, images, and PDF output without tearing down the active playback queue.
- Standby, and the presentation display while nothing is presented, show the standby picture picked in *Settings > Display* (`presentation/standby_image`, a local path), or black when none is set. Blackout is a standby that always shows black and pauses the media; leaving standby ends a blackout.

## 4. Non-Destructive Trim and Viewport Synchronization

- Media trimming uses `trim_start_ms` and `trim_end_ms` metadata passed directly to `libmpv` (`start` and `end` options) without re-encoding files on disk.
- If `trim_end_ms > 0` and `trim_end_ms <= trim_start_ms`, the invalid trim bound is ignored cleanly.
- Image zoom, normalized pan coordinates (`pan_x`, `pan_y`), and PDF page numbers synchronize in real time between the operator preview and the secondary presentation window.

## 5. Meeting Schedule and Background Music Fade-Out

- Ambient background music runs on a dedicated audio-only `libmpv` pipeline isolated from presentation video output.
- Midweek (Monday-Friday) and weekend (Saturday-Sunday) congregation meeting weekdays and start times (`meeting/midweek_day`, `meeting/midweek_time`, `meeting/weekend_day`, `meeting/weekend_time`) are modeled in `MeetingCalendarModel`, persisted per profile, and bound automatically into `BackgroundMusicEngine::configureSchedules(...)` so ambient music initiates a smooth fade-out (default `5000 ms`) tuned to conclude at the scheduled start timestamp.
- Operator pause/fade overrides take immediate precedence over automated scheduling for the remainder of the current session.
- Background music plays the songbook in the media language, inspired by Meeting Media Manager: `sjjm` as MP3, or `sjj` as MP4 for sign languages (`BackgroundMusicLibrary`). The song list is fetched once per language; a song streams from JW.org the first time it plays while it downloads at low priority into `<profile>/Music/<songbook>_<language>/`, and plays from there afterwards.
- The songs are shuffled with a weight that grows with the track number, so newer songs tend to come first (`BackgroundMusicPlanner::weightedShuffle`). Before a meeting of the same day (`MeetingCalendarModel::meetingStartForDate`, honoring temporary schedules and special weeks), the queue covers the time left with that day's songs (`tag_type = 'song'`) played last, and the first song starts late enough for the last one to end at the meeting start; the queue then stops instead of looping. At any other time the shuffled songbook loops.
- With `audio/music_auto_start` on (the default, never in `--demo`), `BackgroundMusicService` starts the music by itself between 75 and 1.5 minutes before a meeting of the same day, unless it was stopped by hand for that meeting, it is already playing, or meeting video or audio is playing. Only a start by hand reports a songbook that cannot be loaded; a failed automatic start tries again after five minutes.

## 6. Network Politeness and Archive Safety

- All catalog and meeting media requests identify `KMedia/<version>` in `User-Agent`, enable HTTP/2, limit concurrent transfers to at most `3` by default (never above `6`), honor `ETag` (`If-None-Match`) and `Last-Modified` (`If-Modified-Since`) with disk-cached catalog JSON payloads so HTTP `304` responses preserve full language and publication metadata across sessions, stream payloads to `.part` files before atomic rename, verify SHA-256 checksums, and use exponential backoff only on transient statuses (`408`, `429`, `5xx`).
- Meeting media syncs on its own (`MeetingSyncEngine`): a rolling window from the Monday of the current week up to 35 days ahead (1 day on a metered connection) plus the weekday offset is kept ready. Every meeting day that is new, failed, or missing synced files is queued (closest meeting first) and synced two days at a time in the background, each into its own date workspace. Past days that failed are marked complete instead of retried. Each day stores its status (`pending`, `syncing`, `complete`, `error`) in `playlists.sync_status`. The date picker marks a day `media` when it holds media added by the operator and its meeting is neither complete nor failed. Changing the schedule, a special week, or a temporary schedule syncs the new meeting days; changing the media language or an extraction filter resets the synced media of the window and syncs it again.
- Midweek: the workbook issue of the week's Monday (an even month reads the previous odd month, primary language then fallback), the document whose `DatedText.FirstDateOffset` is that Monday, its media, and the media of every extract that points at another publication (downloaded and opened the same way, lesson books from their first paragraph), sorted by paragraph. Sections come from paragraph position: from the second song *Living as Christians*, from paragraph 18 *Apply Yourself to the Field Ministry*, before that *Treasures From God's Word*. The Congregation Bible Study media is the media of the two paragraphs before the last item.
- Weekend: Watchtower issues 6, 8, 10 and 12 weeks before the Monday are tried one at a time (primary language, then fallback), stopping at the first issue whose `DatedText` contains that Monday; the study article is the matching `Class = 40` document, and its title becomes the *Watchtower Study* subtitle. Pictures, videos inside the numbered paragraphs, and the opening and closing songs follow the article order; footnote media and paragraph videos follow the extraction filters.
- Circuit Overseer week: the last synced item and the Congregation Bible Study media are hidden in both meetings. Memorial day: the `mi<YY>` background picture and introduction videos.
- Media that is not stored inside a publication is resolved through GETPUBMEDIALINKS (primary language, the extract's own language, fallback), picking the best file at or below 720p; media longer than `2100 s` is streamed. Downloads are prioritized by meeting date (today and tomorrow first). Each `.jwpub` is downloaded once and unpacked once on a worker thread under `<profile>/Publications/<symbol>_<lang>[_<issue>]`, then reused for every week it covers.
- Re-syncing a day merges by `unique_key`: matched items keep the operator's edits (hidden flag, title, trims, section, position), new items are placed after the synced item that precedes them in meeting order, items no longer published are removed, and media added by the operator is never touched.
- The congregation lookup on `hub.jw.org`, the JW language catalog (media language and fallback), and the media filters live in `MeetingCatalogService`; per-week special event rules live in `MeetingCalendarModel`. A `.jwpub` added by hand brings its media into the section the operator picked, without guessing sections from titles. Special weeks: Circuit Overseer (`co_visit`) weeks move the midweek meeting to Tuesday, Memorial (`memorial`) weeks replace the meeting on the Memorial's side of the week, assemblies and conventions suppress both meetings, and temporary weekly schedules (`meeting/temp_schedule_changes_json`) apply to their week only.
- Date-keyed workspaces (`DatabaseManager` Schema V4 `playlists` + `playlist_items`) isolate each congregation profile's daily playlists (`midweek`, `weekend`, `memorial`, `custom`), storing extract groups (`group_key`), colored visual dividers (`item_kind`, `divider_color`), hidden state (`hidden`), editable item tags (`tag_type`, `tag_value`), slide intervals (`slide_interval_ms`), paired background audio (`paired_audio_path`), playback rates (`playback_rate`), restorable sync sort order (`original_section`, `sort_order_original`), the section id of each item (`section_id`), where it came from (`source`: `dynamic` for synced media, `additional` for media added by the operator, `watched` for the watched folder), a stable key for re-sync (`unique_key`), the preview picture of synced media (`thumbnail_path`, V4), and a per-day sync status (`sync_status`, `synced_at`). The V3 migration maps legacy section titles to section ids in place and marks media written by the previous weekly sync as `dynamic`.
- Archive extractors (`.jwpub`, `.jwlplaylist`, `S-34 / S-34mp`) must validate every archive path and entry size cap against directory traversal (Zip-Slip) and decompression bombs before reading or writing data, and convert JW Library 100-nanosecond ticks into non-destructive millisecond trim bounds (`10000 ticks/ms`).

## 7. Cloud Folder Synchronization Rules

- Local Dropbox, OneDrive, Google Drive, and Nextcloud directories are watched recursively through OS filesystem notifications (`QFileSystemWatcher`) with zero disk-scanning timers in steady state.
- Filesystem modification notifications are debounced (`500 ms`) per file and checked for size/timestamp stability and readable archive integrity before importing so partially synced cloud files are never read prematurely.
- The shared folder (`WatchedFolderMedia`) watches only `YYYY-MM-DD` folders directly under the chosen folder (`CloudSyncWatcher::dayFoldersOnly`), skipping folders more than 7 days old. Media files (not `.jwpub` or `.jwlplaylist`) become `source = watched` items of that date, keyed by their path, in the section from the folder's `.section-order.json`, else from an exported name (`NN <Section> - NN <Title>`, or the legacy `Section-<id> - ` prefix), else the day's default section (weekend *Public Talk*, midweek *Living as Christians*, Circuit Overseer week *Circuit Overseer*, other days *Added Media*). Files that leave the folder leave the day; a placement written on another computer moves the item; moving watched items in KMedia writes `{file: {section, order}}` back (order = section number x 1000 + position, written only when it changed). Turning the folder off removes its media from every day. Folders for upcoming meeting days of the sync window are created after each sync, and with *Delete the folders of past weeks* (on by default) folders whose week is over are removed. Watched media counts as added media for the date picker.
- The media export (`MediaAutoExport`) copies each day into `<export>/YYYY-MM-DD/` with `PlaylistExporter`: sections in meeting page order, visible media only, numbered names, files already current skipped, files that no longer belong removed, images and audio optionally converted to MP4 with FFmpeg. It runs after each synced day, a second after the last edit of the open day, and for every meeting day of the window once the sync is idle, on a two-thread pool; a day that changes while it exports is exported again, and folders of weeks that are over are removed. The shared folder and the export folder cannot be the same folder.

## 8. Responsive Operator Console Breakpoints

- The operator main window (`Main.qml`) must support resizing down to a compact side-by-side layout (`minimumWidth: 360`, `minimumHeight: 520`) so operators can run KMedia side by side with Zoom cleanly on `1280x720` and `1366x768` booth displays:
  - **Wide (`width >= 1080 px`):** Three-column desktop workstation (`234 px` left navigation rail, flexible center workspace, `344 px` right live preview and inspector card stack).
  - **Medium (`680 px <= width < 1080 px`):** Narrow icon-only navigation rail (`64 px`), flexible center workspace, and collapsible inspector drawer for 50/50 split screens.
  - **Compact (`width < 680 px`, down to `360x520`):** Single-column stacked workspace with a `54 px` compact bottom tab switcher, icon-only floating pill action strip (`ActionPillBar`), persistent transport + `Standby/Blackout` strip, and toggleable preview drawer.

## 9. Hybrid Booth Integrations (OBS Studio and Zoom)

- `ProcessMonitor` queries running processes (`OBS Studio` and `Zoom`) on a gentle `3 s` interval using lightweight native OS APIs without spawning child shell processes.
- `ObsWebSocketClient` connects asynchronously via `Qt6::WebSockets` (`OpCode 0 Hello` -> SHA-256 challenge auth -> `OpCode 1 Identify` -> `OpCode 2 Identified`) only when OBS is detected or explicitly requested. Scene automation follows three scenes, inspired by Meeting Media Manager: the stage scene (`obs/scene_stage`) while nothing is presented or during standby, the media scene (`obs/scene_media`) while media is presented, paused video included, and the optional image scene (`obs/scene_image`) for pictures and PDF pages, which falls back to the media scene. A scene that is not set leaves OBS where it is. The WebSocket password (`obs/password`) sits next to the host and port in *Settings > Integrations*, and the scenes are picked from the list OBS returns once connected.
- `ZoomBridge` launches meetings via `zoommtg://` with the meeting ID, passcode (`zoom/meeting_pass`), and display name (`zoom/display_name`) set in *Settings > Integrations*.
- Media and background music play on the output picked in *Settings > Audio* (`audio/output_device`, from the devices libmpv lists; empty means the system default). A dedicated Zoom output (`zoom/audio_device`), when set, takes precedence for media playback.
- Direct workspace keyboard shortcuts (`Space`, `B`, `Esc`, `Delete`, `Ctrl+M`, `1`-`2`) automatically yield when any text input field or modal palette has focus, and demo-mode configuration edits stay isolated from persisted congregation settings.

## 10. UI Design System, Theme Persistence, and Meeting Section Grouping

- Icons are the bundled white Lucide and custom SVGs drawn in the requested color by the `icon` image provider (`image://icon/<category>/<name>/<rrggbb>`, only bundled names are accepted) and cached by Qt as plain images; no icon uses a shader effect.
- All QML controls inherit semantic tokens from `Theme.qml` supporting both **Studio Carbon (Dark)** and **Studio Daylight (Light)** modes persisted per profile via `ui/dark_theme` (and overridable at launch with `--theme dark|light`).
- Meeting playlist entries (`PlaylistModel`) store a stable section id instead of a display name: `tgw` (*Treasures From God's Word*), `ayfm` (*Apply Yourself to the Field Ministry*), `lac` (*Living as Christians*), `pt` (*Public Talk*), `wt` (*Watchtower Study*), `circuit-overseer` (*Circuit Overseer*), `imported-media` (*Added Media*), and `custom-<n>` for sections created by the operator. Labels follow the interface language (`MeetingSections::translatedLabel`), custom sections keep the name typed by the operator, and default colors follow the meeting workbook palette (`#3C7F8B`, `#D68F00`, `#BF2F13`, `#945EB5`).
- Section configs (`id`, `label`, `color`, `repeatable`, `collapsed`, `documentTitle`) persist in `playlists.sections_json`. Meeting sections cannot be renamed or removed; removing a custom section moves its media to `imported-media`. Dragging an item across section boundaries or assigning it through the context menu updates only its `section_id`.
- The *Meeting* page (`MeetingMediaPage` over `MeetingDayModel`) opens on the first day from today on, inside the sync window, that has a meeting (midweek, weekend, or Memorial) or added media, falling back to today. Previous and next skip to the nearest such day inside the window, and the date picker only offers the dates of the window, each marked by its status: `complete` green, `error` red, `pending` or `syncing` orange, `media` purple.
- Sections show in this order: the meeting's own sections in meeting order (also when empty, including *Circuit Overseer* in a Circuit Overseer week), then the day's other sections in their stored order, on a meeting day only the ones holding items (hidden items and dividers count). A section that is empty or has hidden media shows a notice row; on a meeting day that is still syncing, empty meeting sections show placeholder rows instead. Collapsing a section keeps only its header.
- Media added without picking a section goes to *Public Talk* on a weekend that is not a Circuit Overseer week; on other meeting days the operator picks the section, and a day without a meeting with a single section uses it. A song is added by its number from the songbook of the media language (`sjj` for sign languages, `sjjm` otherwise) as added media at the end of the section, with its video and preview picture downloading in the background. *Public Talk* and *Circuit Overseer* show a song button while they hold no song.
- JW.org videos (`JwVideoCatalog`) come from the Mediator categories in the media language: `LatestVideos` first, then every category under `VideoOnDemand` (two levels, without the audio described copies), three requests at a time, listed newest first as they arrive and kept for the session. A picked video is downloaded like synced media (MP4 at or below the preferred resolution, streamed past `2100 s`, with its preview picture) into `<profile>/Videos` and added as added media to the picked section.
- The audio Bible (`BibleMediaCatalog`), inspired by Meeting Media Manager, lists the 66 books of the `nwt` recording in the media language (MP3, or MP4 for sign languages; four `GETPUBMEDIALINKS` requests at a time, `booknum` 1 to 66), with the book names JW.org gives in that language; books not recorded in that language are left out. Picked verses add the chapter file (into `<profile>/Bible`, the best MP4 at or below the preferred resolution for sign languages) as added media trimmed from the start of the first verse to the end of the last one through the recording's verse markers, titled like `John 3:16-18` with a `verse` tag; a chapter without verse markers is added whole.
- Study Bible media (`StudyBibleMedia`), inspired by Meeting Media Manager, comes from the `nwtsty` publication in the media language (the fallback language when it is missing), downloaded and unpacked once like the meeting publications. Books and chapters are listed when their verses have media (`VerseMultimediaMap`, without covers, maps, and other decorations: categories 9, 10, and 17), and a chapter lists each picture or video once, at its first verse. Picked media is added like publication media (`DocumentMediaImporter::addRows`): pictures from the publication, linked videos downloaded like synced media with their cover, each tagged `verse` with `chapter:verse`.
- Publication media (`PublicationMediaPicker`) opens a JW.org publication by symbol and issue (`2026-11`, `202611`, and `20261100` name the same issue; the media language, then the fallback) through `PublicationStore`, or a `.jwpub` added from the computer (picked or dropped) unpacked once into `<profile>/Publications/Local/<file name>`. Its documents with media are listed, and a picked document adds its media in document order as added media, with paragraph tags, to the picked section (*Added Media* when none). `DocumentMediaImporter` does the adding for both pickers and downloads the media a document only links to like synced media.
- Public talk media (`PublicTalkMedia`) comes from the congregation's S-34mp, unpacked once into `<profile>/Publications/S-34` and replaced when another file is picked. Talks with media are listed by number (outlines without a number last); a picked talk adds its media in outline order as added media to *Public Talk* (or the picked section), downloads the media the outline only links to like synced media, and sets the talk title as the section subtitle.
- Synced media (`source = dynamic`) can be hidden but not deleted, because the next sync would restore it; media added by the operator can be deleted.
- Several items can be selected on the *Meeting* page, inspired by the Meeting Media Manager media list (`PlaylistModel` selection by entry id, so it follows moves and reloads and is cleared when another day opens): `Ctrl`+click toggles, `Shift`+click takes the visible range between the last clicked item and this one in the order shown, leaving out hidden items and dividers (`MeetingDayModel::sourceRowsBetween`). Hide or show, move to section, delete (added media is deleted, synced and shared folder media is hidden), and drag act on the whole selection; a drag moves it as one block in its order, next to the target and into its section. `Esc` clears a selection of several items before it stops playback.
- The app has two pages, *Meeting* and *Settings*, sharing one header (icon, title, congregation). The calendar, media library, playlists, and downloads pages are gone: the date picker replaces the calendar and playlists, special weeks and temporary schedules are set for the open day's week from the *Meeting* page menu, the congregation lookup, meeting days and times, media languages, and media filters live in *Settings > Meetings*, and the download queue lives in the pill bar popover. Pages other than *Meeting* are created on first use, the preview panel can be put away at any width, and `--tab` accepts `meeting` or `settings` (the old page names open *Meeting*).
- Settings use a searchable two-pane layout (`SettingsView`), whose search matches each category's translated name and keywords ignoring case and accents, with optional per-profile salted SHA-256 Booth PIN protection (`BoothSecurity`, `security/booth_pin_hash`, `security/booth_pin_salt`, gated by `SettingsPinGate`) and startup tab selection (`--tab`).
- Section dividers map custom clean-room monochrome vector glyphs in operator mode while falling back to generic Lucide icons in `--demo` mode, alongside unobtrusive pre/post-meeting readiness checklists (`BoothChecklistPopup`).
- Quick booth actions stay one click away through the enlarged floating `ActionPillBar` (with anchored popovers for display selection, background music playback/fade, live `MeetingTimer` schedule variance tracking, OBS scene/recording control, Zoom booth status, subtitle visibility toggle, and download queue adjustments) and `Ctrl+K` `CommandPalette` using bundled `Inter` typography and vector SVG icons recolored by the `icon` image provider.
